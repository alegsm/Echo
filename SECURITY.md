# Security

## Report a vulnerability

Use GitHub private vulnerability reporting on this repository: open the **Security** tab and select **Report a vulnerability**. Do not disclose an unfixed vulnerability in a public issue. Include the affected version or commit, platform, reproduction steps, expected and observed behavior, and impact. Replace credentials and private transcript content with `<redacted>`.

Private vulnerability reporting is enabled on this repository. If the action is unavailable, do not post sensitive reproduction details publicly. No security email address is published here.

## Boundaries

Echo is a desktop dictation app that sends audio to a provider using the user's credential. Native window identity authorizes commands, OS consent gates microphone access, and provider keys authenticate remote requests. These are separate controls. A renderer-selected label or a successful Check key does not grant OS consent.

Rust owns raw audio, credential resolution, provider calls, SQLite and native paste. Dashboard key drafts pass through the dedicated credential commands. Capture and transcription IPC returns identifiers, text and metadata. Capabilities limit each window; neither renderer can emit arbitrary backend events or use generic clipboard read/write commands. Settings updates, which include registering or removing the login item, and the login item status command are dashboard-only. The overlay can read settings but cannot change them or read the login record. See [IPC and events](docs/architecture.md#ipc-and-events) for authorization and targeted-event disclosure limits.

Provider calls share an HTTPS-only client that rejects redirects, ignores system proxy settings and bounds connect time, request time and response size. Diagnostic events accept fixed fields and omit sensitive payloads. The [architecture reference](docs/architecture.md) owns these mechanisms; [README](README.md#privacy-and-local-data) owns the data inventory, locations and deletion instructions.

Updates cross three boundaries. From the network to Rust, on macOS [updater.rs](src-tauri/src/services/updater.rs) installs only an artifact whose minisign signature verifies against `plugins.updater.pubkey` in [tauri.conf.json](src-tauri/tauri.conf.json), fetched over HTTPS with at most 5 redirects, no system proxy, and connect, request and download timeouts, and only when its version is higher than the running one with no prerelease tag. On Windows, Rust downloads and runs nothing: the Windows build neither registers nor references the updater plugin, reads the manifest under the same transport rules with a 64 KiB limit and takes only its version, which decides whether the download button shows, and the button opens `https://github.com/alegsm/Echo/releases/latest`, a URL compiled into Echo. A forged manifest can at most decide whether the offer shows and which three version numbers it names: the version must be valid semver of at most 128 characters, and only its rebuilt `major.minor.patch` reaches the dashboard and the log. From the renderer to Rust, the dashboard can only read the status and request an update through two commands with no payload; the overlay has neither, and no capability grants an `updater:` permission, so no renderer can choose an endpoint, a key, an artifact or a URL. From the release machine to GitHub, see key custody below. [Architecture](docs/architecture.md#updates) owns the mechanisms.

**Key custody.** The update private key lives only in 1Password and reaches a release build only through the `TAURI_SIGNING_PRIVATE_KEY` environment variable; no script reads it from the repository, prints it or passes it as an argument. Its public half is committed in tauri.conf.json, and until it is, the placeholder `ECHO_UPDATE_PUBLIC_KEY_NOT_SET` makes [update-manifest.ts](scripts/update-manifest.ts) and `build-windows.ps1 -Release` refuse to publish. [update-staging.ts](scripts/update-staging.ts) uses a throwaway key pair under the OS temp dir, and its loopback `http://` endpoint is allowed only by the staging overlay; no shipped config sets `dangerousInsecureTransportProtocol`. Installed copies trust only the pubkey they shipped with. A key that is still held can be rotated by a release, signed with it, that commits the new pubkey; after a lost key, installed copies need a manual reinstall. [Development](docs/development.md#publish-a-release) has the release steps.

## Accepted residual risks

- Providers process uploaded audio and request context under their own policies. Cancellation cannot recall a sent request.
- Local transcript text, prompts and settings are plaintext SQLite data. Filesystem restrictions do not protect them from software running with the user's access.
- Clipboard privacy markers request exclusion. Third-party clipboard managers can ignore them; explicit Copy uses ordinary clipboard behavior. Restoration preserves text only. On macOS, a foreign copy between the final `changeCount` check and restoration can be overwritten. See [delivery](docs/architecture.md#transcript-delivery).
- Storage checks reject symlinked leaf identifier directories, database files and sidecars, including Windows reparse points, but accept redirected ancestors. Ordinary deletion cannot erase backups or retroactively compact free pages from older versions. See [storage](docs/architecture.md#storage).
- The capture energy gate can omit soft speech and brief speech, and later noise after a long pause can pass the gate. Automated signal tests do not establish transcript equivalence. See [capture and segmenting](docs/architecture.md#capture-and-segmenting).
- Find saved key adopts whatever valid item exists under Echo's credential identity for the selected provider; it does not prove that Echo wrote that item. On Windows, software running with the user's access can write that Credential Manager item.
- Native events targeted at the overlay can still reach Tauri listeners using the default `Any` target in another window. The dashboard runtime does not subscribe to partial transcripts; targeting alone is not a confidentiality boundary.
- Echo allows one running copy per app identifier, and a second launch signals the running copy through the single-instance plugin (a Unix socket in `/tmp` on macOS, a named mutex and message window on Windows). Another process of the same user can send that signal. Echo's callback in [lib.rs](src-tauri/src/lib.rs) ignores the arguments and working directory it receives and only shows, unminimizes and focuses the dashboard, so the signal cannot start capture or change settings. It can bring the dashboard to the front.
- On Wayland, Control+Super needs the user in the `input` group. That group lets every process of the user read every input device, so any program the user runs can record keystrokes, passwords included. Echo opens the devices read-only, never grabs them and acts only on Control and Super, but it cannot narrow the group grant. See [Linux sessions](README.md#linux-sessions).
- Start Echo at login writes a per-user record: `~/Library/LaunchAgents/Echo.plist` on macOS, the `Echo` value under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` on Windows and `~/.config/autostart/Echo.desktop` on Linux. Software running with the user's access can edit it. Echo rewrites the record with its own path at startup while the setting is on and the OS still lists it, and turning the switch off removes it, but an edited record runs its own command at the next login until then. The record holds only Echo's path and the `--launched-at-login` argument, which can only keep the dashboard hidden. See [background mode](docs/architecture.md#background-mode).
- Anyone holding the update private key and write access to a manifest endpoint, the GitHub release or echostt.app's update path, can ship code that installed copies install. Endpoint access without the key is not enough, because an artifact signed by another key fails verification. Immutable releases stop the files of a published GitHub release from being replaced. They do not stop someone with write access to the repository from publishing a new release or changing which release is marked Latest, and both update endpoints follow the release marked Latest. On Windows this applies only to installs of 0.5.0, which still install their own updates; later Windows builds only open the releases page.
- On macOS, the manifest's size is bounded only by the 30-second request timeout, not by a byte limit. Windows builds read at most 64 KiB.
- An install starts 10 seconds after the last capture, job or paste. A renderer stalled for longer than that between a job completing and its paste loses the automatic paste to the restart; the transcript stays in History when history is on.
