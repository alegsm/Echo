# Architecture

Echo uses a Rust host and Svelte webviews on macOS and Windows. This reference describes the implementation. [README](../README.md) owns product use, the provider catalog, privacy and local-data instructions. [Development](development.md) owns build commands and acceptance procedures.

## Host and renderers

[tauri.conf.json](../src-tauri/tauri.conf.json) defines the `overlay` and `dashboard` windows. Both enter through [the root page](../src/routes/+page.svelte) at `/?surface=overlay` or `/?surface=dashboard`. [The layout](../src/routes/+layout.ts) disables SSR, and [vite.config.ts](../vite.config.ts) configures SvelteKit 3 with preprocessing, the static adapter and an index fallback. This is a static client-rendered SPA. It has no enhanced form submissions or prerendered pages. Scheduled version polling is disabled; framework focus and visibility checks remain active.

[Package imports](../package.json) map `#lib/*` to `src/lib/*`. Sources include actual file extensions so Bun, Vite and TypeScript resolve the same imports, including dynamically loaded surfaces. [tsconfig.json](../tsconfig.json) extends `$app/tsconfig` and includes source, tests, scripts and root configuration files. The test compiler retains Svelte compilation hooks and uses Bun's native package-import resolution.

Kit 3 checks `/_app/version.json` when a window gains focus or becomes visible. In the packaged static app this reads a bundled local file through Tauri's asset protocol; it contacts no remote host. The installed Kit version exposes `version.name` and `version.pollInterval`, with no supported option to disable these event checks. Setting `pollInterval: 0` disables only the scheduled checks.

[runtime.ts](../src/lib/runtime/runtime.ts) requires Tauri before creating the desktop runtime. WKWebView on macOS and WebView2 on Windows render the UI. Rust owns capture, credentials, provider calls, settings, history and native delivery. Webview process allocation belongs to the platform; the architecture does not depend on a fixed OS-process count.

| Path | Responsibility |
| --- | --- |
| [app_setup.rs](../src-tauri/src/app_setup.rs) | Initializes storage and capture, configures windows and starts the native modifier monitor; cancels owned work on shutdown. |
| [audio/](../src-tauri/src/audio/) | CPAL capture actor, callback blocks, readiness, segmentation, normalization, WAV encoding, artifact cache, leases and device observation. |
| [commands/](../src-tauri/src/commands/) | Tauri adapters, native window authorization, typed validation, settings/history commits and fixed events. |
| [providers/](../src-tauri/src/providers/) | Request adapters, provider verdicts, shared HTTP policy and response bounds. See [the catalog](../README.md#transcription-providers). |
| [storage/](../src-tauri/src/storage/) | SQLite schema, revisions, settings/history validation, retention and deletion cleanup. |
| [services/](../src-tauri/src/services/) | Runtime state, credential resolution, dictation jobs, native transcript delivery, background mode and login registration. |
| [runtime/desktop/](../src/lib/runtime/desktop/) | Native clients, hotkey and capture intent, ordered delivery and revision-aware renderer projections. |
| [dashboard-controller.ts](../src/lib/ui/dashboard/dashboard-controller.ts) and [panel controllers](../src/lib/ui/dashboard/panels/) | Dashboard navigation, drafts, setup and feature interactions used by intact components. |

## Recording to transcript

```text
native modifier or registered shortcut
  -> renderer hotkey and capture-intent controllers
  -> authorized native capture command
  -> capture actor and ordered segment bundle
  -> asynchronous provider requests while capture continues
  -> release and final ordered text assembly
  -> SQLite append and frozen delivery plan
  -> renderer queue in recording order
  -> native clipboard publication and paste
  -> one-shot delivery report and SQLite outcome update
```

The [hotkey controller](../src/lib/runtime/desktop/hotkey-controller.ts) starts capture on the initial press. A release at or before 300 ms latches hands-free recording; a later release finishes it. In hands-free mode, the next press and release finishes the same recording. Releases settle after 80 ms. A re-press before that deadline is bounce and preserves the original press time. Duplicate edges do not repeat capture actions. Physical edge times determine classification; timer delay does not extend the tap boundary. Startup generations and timer cancellation prevent stale work from changing later captures.

The [Windows reducer](../src-tauri/src/platform/windows_hotkey_reducer.rs) ignores injected input and tracks each side of Control, Shift, Alt and Windows. Pressing Control first consumes the subsequent Windows key for the chord. Balanced key-up handling and the existing no-op pair suppress unintended Start-menu activation when Windows was already forwarded. [Hook health](../src-tauri/src/platform/windows_hook_health.rs) detects failures using passive input evidence, bounds recovery attempts and resynchronizes modifier state. While the native monitor is unavailable, the configured fallback toggles recording. After a silent removal, a reinstalled hook keeps the fallback active until it receives its own first callback, so input that the hook cannot see (for example typing in an elevated window) does not flip availability back and forth. Recovery cancels current intent before restoring native capture, which is why availability must not flap.

On macOS, [permissions commands](../src-tauri/src/commands/permissions.rs) authorize Fn preference reads and writes only for the dashboard. Enabling capture does not change the system Fn action. An explicit preference change saves the previous value or absence for restoration. Unrecognized values are displayed but cannot be overwritten by Use Fn. OS permission responses remain separate from this preference.

## Capture and segmenting

[audio/types.rs](../src-tauri/src/audio/types.rs) defines capture policy and metadata. [audio/backend.rs](../src-tauri/src/audio/backend.rs) owns the CPAL lifecycle on an actor. The callback fills preallocated PCM blocks under a short queue lock. The actor drains them every 20 ms, returns processed blocks to the pool and releases the callback lock before segmentation and encoding. After selecting the device format and before play, capture installs a sized PCM block pool. Its explicit `PcmHeadroom::StallBudget` setting defaults to ten seconds of device audio (or the cap if shorter), independently of segment cuts. Tests can set a byte budget to reproduce constrained pools. No PCM pool is allocated before format selection. Admission failure returns before recording. Accounting covers queued and actor-held samples until recycling; cumulative sample telemetry remains separate. Drained queues recycle remaining blocks on early return. Pool exhaustion drops only overflow samples, increments the dropped-callback counter and reports the PCM limit once. It keeps the recording and every accepted sample for normal stop and transcription. At 192 kHz with eight channels, the ten-second budget holds 15,360,000 samples; 3,751 blocks including the spare reserve 61,456,384 PCM bytes (58.61 MiB). Three descriptor queues add 270,072 bytes on 64-bit targets, for 61,726,456 bytes excluding allocator metadata and other capture/segmenter state. `Opening` and `WaitingForFirstCallback` stay `requesting_microphone`; a confirmed callback is required before `recording`.

CPAL reports open, build and play failures and stream callback errors as one typed `cpal::Error`. [backend.rs](../src-tauri/src/audio/backend.rs) classifies all four stages the same way: `PermissionDenied` becomes `MicrophonePermissionDenied`, `DeviceNotAvailable` becomes `DeviceUnavailable` and `StreamInvalidated` stays `StreamInvalidated`. Every other kind keeps its stage code (`DeviceConfigFailed`, `StreamBuildFailed`, `StreamPlayFailed`, or `StreamBackendError` for callbacks), so a synchronous failure is never treated as recoverable. A missing default input device is `MicrophoneUnavailable`. On Windows, CPAL 0.18.2 leaves `E_ACCESSDENIED` as an unmapped `BackendError` whose message carries the HRESULT; only that kind is read for denial codes and privacy-setting text, and a typed kind always wins over its message. Callback notifications follow one policy. `Xrun` becomes a nonterminal `stream_error` event with `BufferUnderrun`. `DeviceChanged` becomes an informational `audio_route_changed` event and keeps the stream. `RealtimeDenied` is ignored. Every other kind ends that session. One actor handler applies this policy both while waiting for the first PCM and while recording. The callback-to-actor event queue is bounded and drops on full, so a burst of underrun or route warnings can crowd out other events. Each capture therefore latches its first terminal error and its readiness, and the actor reads both after each drain, so only warnings can be lost. A drain handles at most one queue-sized batch of 32 events before that latch check, because sustained overload can refill the queue as fast as the actor empties it; cancellation, the first-callback deadline and commands are checked between batches. Recoverable notifications never mark capture ready or extend the first-callback deadline. A terminal notification emits its idle event, releases ownership, discards the bundle and drops the stream. Events from an older generation are dropped in the callback and again in the actor.

The backends differ. CoreAudio binds an input stream to its device and reports `DeviceChanged` only for default-output changes, `Xrun` for processor overload, `StreamInvalidated` for a sample-rate change, and `PermissionDenied` when consent is refused. WASAPI reports a removed or replaced default input as `DeviceNotAvailable` or `StreamInvalidated`, and capture xruns as `Xrun`. Neither backend reroutes capture to a new default input. Owner-visible default-input classification is unchanged: device observation runs only while Debug log is on, and the macOS observer does not listen for default-input changes. The three-second CPAL timeout bounds CoreAudio's wait for the device sample rate; a timeout there reports `DeviceNotAvailable`, so the native code is `DeviceUnavailable`. The owner sees it as `microphone_unavailable` whether it rejects the start command ([desktop-error.ts](../src/lib/runtime/desktop/desktop-error.ts)) or arrives as a capture event ([services/runtime.rs](../src-tauri/src/services/runtime.rs)). It does not bound every backend's build. Native default configs keep the device format (CoreAudio reads the stream format, WASAPI the mix format), and the callback converts every supported integer and float format to `f32`. Fakes prove the actor policy and typed values prove the mapping. Neither proves OS callbacks, driver sample packing or microphone release, so [physical acceptance](development.md#physical-acceptance) on macOS and Windows must cover consent grant and denial, absent input, unplug, default switch, retry, ordinary stop and cancel, audible capture, device formats and recoverable overload where reproducible.

[audio/segmenter.rs](../src-tauri/src/audio/segmenter.rs) measures age in device frames. From two seconds, a complete 500 ms quiet window can close a piece. From six seconds, a complete 250 ms quiet window can close it. From twelve seconds, the quietest 100 ms frame in the trailing second provides a cut without requiring quietness. The fallback closes continuous speech at about twelve seconds. Remainders retain their samples, and the recent capture reference continues across cuts. No cut rule guarantees an intact word.

Quiet RMS and peak limits are the greater of the policy floor and a quarter of the corresponding measure over the trailing three seconds. Default floors are 0.003 RMS and 0.02 peak. A speech-bearing piece needs a non-quiet 10 ms block with at least 120 ms of non-quiet blocks in its trailing 200 ms window, plus the encoded signal gate. Release trims to 400 ms after the last qualifying block, clamped to available samples. Silent pieces retain ordinals without encoded bytes; an entirely silent capture returns `LowSignal`.

The energy gate can omit soft or brief speech. A pause longer than about 4.5 seconds can fill the reference with noise and allow later noise to upload. These rules operate with diagnostics disabled too. [resample.rs](../src-tauri/src/audio/resample.rs) downmixes, sanitizes non-finite samples and applies a Blackman-windowed sinc filter before resampling. [wav.rs](../src-tauri/src/audio/wav.rs) encodes mono 16 kHz PCM16. Session metadata retains device format; artifact metadata describes encoded format.

### Resource limits

The limits are implemented in [audio policy](../src-tauri/src/audio/types.rs), [the artifact store](../src-tauri/src/audio/artifacts.rs), [dictation](../src-tauri/src/services/dictation.rs), [job admission](../src-tauri/src/services/transcription_jobs.rs) and [the capture registry](../src-tauri/src/commands/stt/segments.rs).

| Resource | Bound |
| --- | --- |
| One capture | Ten minutes, derived from `MAXIMUM_CAPTURE_DURATION`. The deadline uses ordinary stop and retains the sealed bundle for transcription. |
| One bundle | Cap × 16 kHz × two bytes, plus header and rounding allowance for each derived ordinal (19,213,846 bytes). |
| Encoded cache | Four bundles × the bundle budget (76,855,384 bytes); recording and leased bundles cannot be evicted. Full bundle capacity is reserved before capture starts. |
| Artifact lifetime | Sealed, unleased bundles expire after 60 seconds; leases last 45 seconds and pause expiry. Release work renews leases every 20 seconds. |
| Logical work | Six active jobs and six registered dictations. |
| Provider work | Six shared request permits, including probes, repairs and whole-audio fallback. |
| Repair work | One shared repair slot; at most three attempts per dictation, only below 60 seconds. |
| Ordinals | ceil(cap / two-second minimum cut) + one tail = 301 entries, including silence. |
| Abandoned dictation | 60 seconds of inactivity before registry removal and runtime retirement. |

Cache and job capacities are independent. Four protected bundles cause `ArtifactCapacityReached` rather than eviction of live audio. Submitted requests own their bytes through `Arc` and need no cache slot; probes use no bundle. Excess requests wait for permits while capture continues. Cancellation wakes queued dispatchers so they drop audio without waiting for a slot. Ordinary in-flight requests retain permits until they exit.

Native maintenance emits elapsed and limit milliseconds with capture identities at each native elapsed second. Progress travels on `echo-audio-capture` without advancing or broadcasting a desktop state envelope. The desktop runtime projects matching events as typed `recording_progress` events; the overlay can derive a countdown from native time. Terminal events retain intent, session and artifact identity. Matching automatic completion consumes the renderer intent once through ordinary stop, transcription and ordered delivery. Manual-stop races cannot consume it twice. A held shortcut remains suppressed until physical release after automatic completion; the next fresh press can start capture.

Recording pins a bundle against expiry and eviction. Release seals it and starts idle expiry. Cancellation, capture failure and owner exit discard recording bundles. Terminal provider completion discards sealed audio on both success and failure. Starting a new capture leaves older provider work independent. Registry deadlines are replaced by segment, artifact and successful terminal idle events; release and cancellation disconnect them. Error idle cancels only the registry entry named by the event's intent; a delayed older terminal event cannot retire a newer capture.

## Ordered jobs and repairs

[commands/stt/segments.rs](../src-tauri/src/commands/stt/segments.rs) schedules leased bundle snapshots outside the capture actor. Each non-silent ordinal is dispatched once. The first dispatch freezes provider, language, prompt, Phrasebook terms and clipboard settings. If no piece was dispatched, release freezes them before waiting for capacity. No previous transcript is added to a request. [Credentials](../src-tauri/src/services/credentials.rs) resolves only the selected provider's OS credential account, gated by its saved marker. Frozen jobs carry no credential source or key.

[dictation.rs](../src-tauri/src/services/dictation.rs) coordinates results. Silence, empty verdicts and whitespace contribute no text, but retain their ordinal positions. [stitching.rs](../src-tauri/src/services/dictation/stitching.rs) strips edge ellipses, preserves internal spacing and punctuation, and collapses a case-insensitive seam overlap of at least three words with at least two distinct words. Repeated single words remain. The closed function-word rule in that module lowercases eligible leading words after an unfinished sentence; names, acronyms and other words remain. Surviving pieces join with one space. Preview text advances past completed speech, silence or exhausted failures. A retryable piece failure retries once with the frozen settings, while retaining its shared provider permit. Non-retryable failures, including missing or rejected credentials and invalid audio, contribute a gap immediately. Later ordinals keep running after an exhausted retry. Each failed ordinal contributes “[Transcription gap]”. Assembly cleans each successful run separately, so overlap removal never bridges a gap.

Valley cuts and collapsed overlaps make a seam doubtful. Groq also uses joining-edge confidence: absent or invalid evidence, `avg_logprob <= -0.75` or `no_speech_prob >= 0.60` makes it doubtful. Other providers use structural signals. Repairs join exactly two adjacent speech pieces; they never bridge silence. Each repair acquires the single shared repair slot before a normal provider permit. Failed, empty or confidence-rejected repairs preserve the original text.

Groq alone also drops a phantom closer by loudness. After each reply (every piece, repair and whole-WAV fallback, since each carries its own WAV), [groq.rs](../src-tauri/src/providers/groq.rs) scans segments from the end and drops one whose audio window, taken from Groq's `start`/`end`, stays far below that same upload's speech. [tail_level.rs](../src-tauri/src/audio/tail_level.rs) measures 20 ms RMS frames: the speech level is the RMS a quarter of the frames at or above the 0.003 signal floor reach, and a frame is at speech level when it reaches 0.1 times that (-20 dB; `TAIL_RATIO`). The rule judges how long the window stays at speech level, not what share of it does: the tail is quiet when at least 300 ms of the window lies inside the audio (`MIN_TAIL_MS`, an end past the audio being clamped) and under 120 ms of it is at speech level (`MAX_TAIL_SPEECH_MS`, the segmenter's shortest speech run). The first kept segment stops the scan; the first segment and interior segments are never dropped by level, and missing or non-finite timestamps, a WAV that is not the upload format or a recording below the floor keep everything. The existing no-speech rule still applies. Each piece is judged against its own level, and stitching and the live preview read the filtered results; there is no pass over stitched text. With Debug log on, one `quiet_tail_check` record per reply of two or more segments carries the decision, its reason, the window, the time at speech level, the levels and their ratio, never text. Known limits: a phantom timed to overlap the last real word by 120 ms or more is kept; a piece cut on a 250 ms quiet window may leave a window too short to judge, so its phantom is kept; a real closing word is dropped when its window catches under 120 ms of it at speech level, whether the word is that short or its timestamp starts late; a sustained closing phrase more than about 20 dB below its piece's speech level is dropped, and bursty speech raises that level. Other providers return no usable segment timestamps and are unchanged.

Original results remain immutable for preview. Below 60 seconds, final assembly selects accepted disjoint repairs from left to right, so an earlier successful pair wins over an overlapping later pair. Release awaits only the eligible last speech seam and retires older pending repairs. At 60 seconds and above, all repairs are discarded and the original cleaned stitch remains. Empty or silent results do not trigger whole-audio fallback. An exhausted genuine piece failure below 60 seconds starts one strict whole-WAV fallback after all original pieces settle and pending obsolete repairs retire. Usable whole text replaces the partial stitch; a failed or empty fallback retains the stitch and its gaps. At exactly 60 seconds and above, neither repairs nor whole-audio fallback contributes text.

Only release finalizes, appends one final transcript and returns a delivery plan. Cancellation suppresses publication from queued and in-flight work. An already-sent request can remain active until its 30-second bound. Partial rows store `provider_failed`. Delivery updates preserve that code while recording the insertion outcome. A completion without successful speech is saved with insertion mode `failed`, without automatic clipboard or paste delivery, and receives no native delivery authorization. Speech-bearing completions start in `manual` mode, even if the recognized words match the marker text. Successful text remains deliverable if persistence fails, and insertion failure cannot erase a saved transcript.

The shared [provider client](../src-tauri/src/providers/mod.rs) requires HTTPS, rejects every redirect and uses a 10-second connect timeout within a 30-second overall request timeout. Response reads stop at 2 MiB. Probes and all transcription forms use the same client pool. Test clients explicitly permit loopback HTTP while retaining redirect rejection. [probe.rs](../src-tauri/src/commands/stt/probe.rs) checks the configured key using a generated silent WAV without acquiring the microphone.

A saved language reaches each provider as it was saved or as its two-letter primary subtag ("pt-BR" is sent as `pt` to OpenAI, xAI, ElevenLabs and Mistral; Groq and Deepgram receive the tag as saved). Auto-detect saves no language, and no adapter substitutes English for it, because each provider detects the spoken language when none is sent. [providers/mod.rs](../src-tauri/src/providers/mod.rs) `primary_language` returns nothing for it, and a tag with no two-letter primary subtag (such as "fil") counts as none for the providers that take one. With Auto-detect:

| Provider | Sent |
| --- | --- |
| Groq | No `language` part. |
| OpenAI | No `languages[]` part. |
| xAI | No `language` and no `format` part: xAI rejects `format` without `language`, so Auto-detect output comes back without its text formatting. |
| ElevenLabs | No `language_code` part. |
| Deepgram | `language=multi`, its multilingual mode, because Deepgram assumes English when the parameter is missing. Keyterms are still sent. |
| Mistral | No `language` part. |

The Phrasebook part of the prompt that Groq and OpenAI receive follows the same rule, because Groq expects the prompt in the audio's language. [settings.rs](../src-tauri/src/commands/stt/settings.rs) `transcription_prompt` uses the English sentence ("This is English dictation for software and product work. Use these exact spellings when heard: ...") only when the saved language's primary subtag is `en` (`en`, `en-US`, `en-GB`). With Auto-detect and with any other saved language it sends only the terms, joined with ", " and ending with a full stop, so it carries no English sentence. Terms that are English words, and an English custom prompt, can still bias the model. The custom prompt is the user's own text and is passed through unchanged in every case.

The provider check in `probe.rs` keeps an explicit English language and is unaffected. Known limit: each piece of a long recording is detected on its own, so a very short piece can be detected wrongly, for example as another language, and choosing a fixed language avoids that.

The sealed native artifact carries the `Instant` from stop entry through final assembly. Typed dictation completion carries that wall duration and partial/speech status into persistence. Stored timing keys and old rows stay readable without rewriting: `recording_ms` is captured duration, `stop_to_transcript_ms` is wall time from native stop entry to final assembly, and `provider_ms` is aggregate provider request time across pieces, retries, repairs and fallback. Parallel requests can make the aggregate larger than wall time; work completed during recording contributes only to the aggregate. `backend_ms` retains the aggregate value for compatibility, and `blob_ready_ms` and `upload_ms` remain zero. Historical `stop_to_transcript_ms` values keep their earlier aggregate meaning.

## Transcript delivery

The renderer's recording-order queue lets provider jobs overlap but invokes native delivery once per final result. [transcript_delivery.rs](../src-tauri/src/services/transcript_delivery.rs) serializes automatic delivery and explicit Copy through one process-wide lock, with eight admitted operations. Excess calls fail with `clipboard_failed`. The overlay alone may call `deliver_transcript`; both known windows may call `copy_transcript`. Validation rejects unknown fields, NUL text and text above 2 MiB.

With automatic paste and restoration enabled, the service snapshots text, publishes protected transcript text, waits 250 ms, pastes, waits 150 ms and conditionally restores. Restoration requires matching clipboard generation and text. Snapshot failure skips restoration; publication or privacy-marker failure prevents paste; insertion failure reports `insertion_failed` after conditional cleanup. Disabling paste leaves protected copied text. Disabling restoration leaves text after paste. Explicit Copy uses ordinary clipboard behavior and no delivery outcome report.

macOS publishes `org.nspasteboard.TransientType` and `org.nspasteboard.ConcealedType` on the same item before Cmd+V. It checks `NSPasteboard.changeCount` and text before restoring. AppKit has no compare-and-swap: a foreign copy between the check and restoration can still be overwritten.

Windows publishes `ExcludeClipboardContentFromMonitorProcessing`, plus zero values for `CanIncludeInClipboardHistory` and `CanUploadToCloudClipboard`, before Unicode text. It compares `GetClipboardSequenceNumber` and restores under a clipboard lock. Native code releases and restores all eight modifier sides around Ctrl+V and tags injected events. Partial insertion fails without replaying paste; modifier recovery is bounded and best effort.

Preservation is text-only; images and files are not restored. Third-party clipboard managers may ignore exclusion requests. A one-shot native ownership proof lets saved results update their SQLite delivery outcome; delayed reports cannot overwrite newer revisions. Unsaved transcripts still deliver without that report. Clipboard content and native error detail do not return to renderer snapshots.

## Storage

[Storage setup](../src-tauri/src/commands/storage/setup.rs) publishes `EchoStorage` only after database opening, schema initialization and a successful settings read. A schema or settings-read failure aborts setup. Settings/history stay authoritative in SQLite. Renderers keep revision-aware projections; the native runtime keeps only the current transcript rather than a second history store. See [README](../README.md#locations) for current paths and [deletion guidance](../README.md#delete-local-data).

[database.rs](../src-tauri/src/storage/database.rs) enables and verifies `secure_delete=ON`. Deletion, clear and retention commit under the storage mutex, then run checked `wal_checkpoint(TRUNCATE)` outside the transaction. A busy or failed checkpoint leaves committed state available with `cleanupStatus: "pending"`. A later purge or launch attempts cleanup again. Empty clear can perform pending cleanup without advancing history revision. Listing-triggered retention publishes its committed revision to the other window. This does not retroactively compact older free pages or erase backups.

[settings.rs](../src-tauri/src/storage/settings.rs) infers missing saved-key markers from the raw legacy row, then discards exactly `turboModeEnabled`, `providerEnvVarNames` and `providerCredentialModes` before strict saved-row validation. Malformed retired fields are ignored. Reads preserve JSON and revisions; the next successful write omits retired fields. Command patches reject them, saved-key markers, secrets and unknown fields. Live provider IDs, statuses and markers stay strictly validated. Schema version remains 1. There is no transcript-edit command or storage write path.

[The managed credential service](../src-tauri/src/services/credentials.rs) owns current-identity entry construction, save verification, deletion, saved-key search and use-time resolution. Registration constructs no OS entry. Per-provider locks cover the OS operation, metadata commit and settings publication. Verified saves set `providerKeySaved` true; removal, including NoEntry, sets it false. Use-time NoEntry clears the marker and publishes the settings revision before returning a missing-key error. Denied reads and provider rejection preserve the marker. Revision conflicts retry only metadata, and metadata failure withholds success without a compensating OS operation. Find takes the same provider lock and reads settings first. A true marker returns `already_saved` without constructing an entry; otherwise it reads the current-identity item once. Only a valid item, nonempty after trimming and at most 4 KiB, commits the marker and then publishes the settings revision (`found`). A missing item (`not_found`), an unusable item (`invalid`) or a failed read (`unavailable`) leaves metadata unchanged, and a failed read carries no OS detail. If the marker commit fails after a valid read, Find returns `save_failed` without publication. Find never writes or deletes the OS item, and the key never leaves Rust. Errors are reserved for authorization denial, unknown providers, an unavailable lock or task, and settings that cannot be read before the search. A failed task and the pre-search settings failure use the fixed message “Saved key search failed. Try again.”, never the metadata-commit message. Renderer patches cannot set the marker.

Legacy settings infer the complete marker map only when `providerKeySaved` is absent: literal providers with valid, unchecked or invalid status infer true; other providers infer false. Explicit false survives old statuses. Reads preserve the stored row; the next write persists the map with schema version 1. Before running an older build, back up the database and restore the retired mode map required by that build. Builds predating saved-key metadata also require removing `providerKeySaved` from the recovery copy. Reverting code alone does not restore retired JSON fields. Echo 0.3.2 cannot read a settings row written after `runInBackground` and `launchAtLogin` were added: `PersistedSettings` in [models.rs](../src-tauri/src/storage/models.rs) denies unknown fields, so the older read fails and setup aborts. Any settings write on a build with these fields stores both keys. Before running 0.3.2 again, restore a database backup or remove both keys from the `value_json` of the single `settings` row.

[The native bootstrap](../src-tauri/src/app_setup.rs) registers the credential service (Tauri keeps the first managed value, which lets tests inject a counting store), opens and initializes current storage, and loads the saved settings into `EchoRuntime`. Production runtime initialization calls this same bootstrap before capture and window setup. From bootstrap through the first dashboard presence query and repeated refreshes, no credential entries are constructed and no credential reads, writes, deletion or provider probes occur. Opening Settings or setup does not access the store; only an explicit Find saved key, save, Check key, removal or dictation does. Presence reads only saved-key markers through the authorized native dashboard command. [The startup tests](../src-tauri/src/app_setup_tests.rs) drive this chain with Tauri's mock runtime and a counting store; native path resolution, capture and window event wiring still require host acceptance.

The current `app.echostt.desktop` identifier supplies app directories and the credential service. Windows requires absolute `LOCALAPPDATA` without parent traversal or a roaming fallback. Startup opens only the current database; other install directories and stale filesystem receipts are ignored. Deleting current local data starts an empty database on the next launch. [database.rs](../src-tauri/src/storage/database.rs) refuses symlinks or Windows reparse points at the leaf identifier directory, database and sidecars before opening SQLite. Redirected ancestors remain accepted.

Startup reads no renderer localStorage. The retained `legacy_migrations` SQLite table contains opaque receipt rows that runtime code never reads, parses, updates or deletes. Schema version remains 1.

Provider requests use [the shared HTTP client](../src-tauri/src/providers/mod.rs), which ignores system proxy settings, requires HTTPS, refuses redirects and retains 10-second connect and 30-second overall timeouts.

## IPC and events

[Capabilities](../src-tauri/capabilities/) grant operations per window, and [window_authorization.rs](../src-tauri/src/commands/window_authorization.rs) checks native identity. Capture ownership binds window, session, original intent and purpose. The dashboard has no capture grant; credential entry and settings mutation require dashboard authorization. OS microphone consent and provider authentication are additional independent boundaries.

Capture and STT use nested `{request: {...}}` payloads; credential commands retain small flat payloads. The dashboard-only saved-key search takes `{providerId}` and returns only `{outcome}` (`found`, `not_found`, `invalid`, `unavailable`, `already_saved` or `save_failed`); an adoption publishes only its settings revision, with no credential notification. Responses expose identifiers, transcript text and metadata, never raw capture bytes or resolved keys. The dashboard-only `get_launch_at_login_status` command takes no payload and returns `{registered}`; see [background mode](#background-mode). Dedicated credential commands receive dashboard drafts. Neither capability grants generic event emit, clipboard read/write or generic log calls. Rust publishes fixed event names after authorized operations.

| Native event | Projection |
| --- | --- |
| `echo-audio-capture` | Capture identity, phase, sequence and outcomes. |
| `echo-desktop-state` | `{sequence, snapshot}` from [runtime.rs](../src-tauri/src/services/runtime.rs). |
| `echo-stt-job` | Job-scoped lifecycle and completion. |
| `echo-partial-transcript` | `{dictationId, ordinal, text, status?}` deltas and immediate retry/gap/recovery status targeted at the overlay. |
| `echo-settings-committed` | Committed settings revisions and changed fields, published through the typed emitter in [storage/events.rs](../src-tauri/src/commands/storage/events.rs) for storage, credentials and STT. |
| `echo-history-committed` | Committed history revisions. |
| `echo-credentials-updated` | Successful credential set/delete `{action, providerId}` notifications. |
| `echo-fn-hotkey` | Native modifier edges and availability. |

Renderer projections subscribe before reading snapshots and reject stale sequences, revisions, foreign identities and duplicate ordinals. Active capture takes precedence over older provider work. New capture identity and job sequence determine settled outcomes without suppressing older job-scoped results.

[The partial publisher](../src-tauri/src/commands/stt/events.rs) uses `emit_to("overlay", ...)`. Tauri's default `Any` listeners in another window can still receive targeted events; targeting is not a confidentiality boundary. The dashboard runtime never subscribes to partials. [partial-transcript-state.ts](../src/lib/runtime/desktop/partial-transcript-state.ts) requires a matching ordered segment-closed event before ordinary preview text is eligible; status notices are independently eligible. Release-tail text alone cannot enable it. Status events bypass text ordinal ordering and retain the underlying preview. A chalk retry or gap notice occupies the existing preview region for four seconds. A new status restarts that interval; ordinary partial text does not. The live preview then returns with all retained words, while the countdown remains in its capsule above it. Gap markers remain in the final text and History. Release, cancellation and matching terminal idle failures clear preview state; nonterminal PCM and underrun reports preserve it; stale completions cannot clear newer text. Partial text has no history or clipboard delivery path. Final text alone uses those paths.

[diagnostics.rs](../src-tauri/src/diagnostics.rs) authorizes structured renderer events by native window and committed settings. Native code supplies time, surface and build provenance. Only closed event and field values survive filtering, canonical UUIDs qualify as attempt IDs, and records are bounded to 4096 bytes. [README](../README.md#privacy-and-local-data) lists excluded data and log limits. Device observers do not prove CPAL device identity or OS release acknowledgement; the macOS observer does not subscribe to CoreAudio default-route changes.

## Dashboard and overlay

Dashboard rendering uses [particle-field.ts](../src/lib/ui/dashboard/particle-field.ts) beneath the frosted panels. Its backing scale is max(1, capped DPR × 0.5), with DPR capped at 2. DPR 1 retains CSS resolution, and DPR 2 renders at half device resolution. Point sizes and culling margins preserve main's CSS geometry at each DPR. One requestAnimationFrame loop limits drawing to 30 fps, retaining all 21,600 projections and reusing column and row wave calculations with integer column and row loops. Window dimensions and DPR are read on resize rather than on every draw. Pauses freeze elapsed field time; reduced motion displays the time-zero pose without a recurring loop. Resizing in the background is deferred until rendering is eligible, except that reduced motion immediately redraws its still pose.

[dashboard-motion.ts](../src/lib/ui/dashboard/dashboard-motion.ts) observes window focus and blur, document visibility and live reduced-motion changes. Recurring dashboard motion requires focus, a visible document and normal motion. [DashboardApp.svelte](../src/lib/ui/dashboard/DashboardApp.svelte) applies the shared CSS pause attribute to descendants and pseudo-elements and passes eligibility to the navigation mark. Intersection observers also pause glow hosts, the mark and the provider checking light when clipped outside their scroll viewport. A provider check can still settle its result while its decoration is paused. Actual field draws publish a document-scoped frame tick for the glow and navigation mark. The mark keeps its standalone frame loop when no shared clock is supplied. Unmount removes frame subscriptions, observers, event listeners, animation frames and shine timers.

[dashboard-tokens.css](../src/lib/ui/dashboard/dashboard-tokens.css) draws one static bright glow layer. Its paused opacity animation follows the field tick through cached Web Animations objects, retaining the 4.8-second ease-in-out cycle from 1 to 0.85 and back without animating box-shadow or creating frames between field draws. Reduced motion holds the static appearance, and increased contrast keeps a constant glow.

Dashboard components use feature-local controllers for History, Phrasebook, Settings and setup. Empty API-key drafts are initialized only in `initialDashboardState`; initial settings responses and settings events never write them. Provider checks hold nonempty drafts in a pending acknowledgement tied to provider, draft and panel lifetime. The labelled native dialog explains the platform store, focuses Cancel and traps Tab. Cancel or Escape releases the pending lock before returning focus to the key field. Every replacement requires a fresh acknowledgement. Acknowledgement saves and verifies the key, clears only the matching draft, resets its status, then probes. [DesktopRuntime](../src/lib/runtime/desktop/desktop-runtime.ts) awaits a committed-settings reload after native credential save or deletion succeeds, before the controller writes status. This prevents a delayed settings event from leaving the renderer at the pre-mutation revision. A status-only provider patch retries once after a revision conflict, using the settings store's reload before rejection. Other settings writes retain strict conflict handling. Initial settings hydration updates the hotkey draft only while it still matches the previous saved shortcut. Unmount discards pending consent while preserving the lock for running native work. A dashboard-scoped lock and identity checks prevent stale checks from replacing newer drafts or statuses. Find saved key appears only while the selected provider is not configured, including in setup, and runs only when pressed. It shares that lock with Check key and Remove key. DesktopRuntime reloads committed settings only after `found`, and a failed reload still returns the native outcome. On `found` the controller resets the provider status to unchecked and refreshes presence; `already_saved` and rejected searches refresh presence. A failed reset or refresh after `found` keeps the found message. `save_failed` reports that the key was found but not saved; any rejection reports “Saved key search failed. Try again.” and never claims a key was found. When presence then reports the key, the button unmounts and focus moves to Check key, otherwise it returns to Find saved key; either move happens only if focus was not claimed elsewhere. After a provider change the result is discarded. After an unmount the status reset and presence refresh still run, but the message and focus are dropped. Native credential presence returns booleans from committed `providerKeySaved` metadata. Provider checks and transcriptions persist credential rejection or success; transient failures preserve the applicable status. Settings, events, SQLite and diagnostics contain no key values.

[dashboard-controller.ts](../src/lib/ui/dashboard/dashboard-controller.ts) supplies the alert label and message together. Boot errors precede action errors, which precede snapshot errors. A missing provider key uses “Provider setup”; provider timeouts and failures use “Network Failure”; other snapshot errors use “Action failed”. The intact dashboard renders this result and removes the alert when errors clear.

History confirmations use the shared EchoPopup HTML modal with token buttons, focus trapping, Escape and trigger focus restoration. Provider key removal instead uses the actual local `<dialog>` in [ProviderPanel.svelte](../src/lib/ui/dashboard/panels/ProviderPanel.svelte), with component-local dialog and button styles and [provider-controller.ts](../src/lib/ui/dashboard/panels/provider-controller.ts) handlers. It is not built from EchoPopup. [history-controller.ts](../src/lib/ui/dashboard/panels/history-controller.ts) commits confirmed mutations; cancellation leaves records unchanged.

The overlay uses native placement and serialized sizing with compact, preview and expanded shapes. Partial words have stable identities and arrival times. Release removes preview words immediately and returns the shell; generation guards protect new recordings from older timers. Reduced motion settles animation immediately. [The brand guide](../design/brand/README.md) owns mark animation and artwork cuts; [README](../README.md#contribute) owns ParticleHalo attribution and license locations.

[The overlay controller](../src/lib/ui/overlay/overlay-controller.ts) uses typed `recording_progress` events for the final-minute warning. It binds progress to the capture-begin intent, rejects regressing elapsed time and foreign sessions, and derives the displayed seconds as `max(0, ceil((limitMs - elapsedMs) / 1000) - 1)`. No renderer timer advances the countdown. Stop, cancellation and a new intent clear the warning. Holds and hands-free recordings share this path. A separate live region keeps one stable announcement per intent; visible ticks remain readable on demand outside live regions.

The warning and transcription notice retain the existing 380×144 preview shape with the orb cell at 150,64. Its countdown sits in a small dark glass capsule above the preview content; expanded details reserve a line above their content. [The shell stylesheet](../src/lib/ui/overlay/overlay-shell.css) pulses a bright halo and outline layer from opacity zero to one at 1 Hz over a steady dim-red base. Both pulse layers enter in the same style pass; their parent wrappers own morph opacity. The halo's base circles share the bright circles' geometry and frame loop. Pulse wrappers and base circles mount only during warnings, keeping the ordinary halo SVG as a direct child of its morph wrapper. Reduced motion holds the red light steady. The outline retains its 2.4-second perimeter lap and 128-piece tail. Its static line has the reference's tight tinted shadow in a separate SVG. The moving tail has a 2 px core above 4 px and 8 px unfiltered strokes at 24% and 8% opacity. Both bloom layers use 32 nested dashes with the core's head position and linear taper; the core retains 128 pieces. All three layers share the same tint and one sweep-position custom property. The head ends cleanly without a separate sprite.

[OverlayApp](../src/lib/ui/overlay/OverlayApp.svelte) owns live document visibility and reduced-motion listeners and removes them on unmount. It passes current preferences through the surface and settles finite colour and speed transitions when visuals are suppressed. Terminal feedback uses a four-second timer independently of visual frames. Document visibility is the only occlusion signal; packaged WKWebView occlusion still requires host verification.

[OverlaySurface](../src/lib/ui/overlay/OverlaySurface.svelte) passes explicit motion eligibility to the halo and outline. Expansion, document hiding and reduced motion stop visual loops immediately. Halo work stops after its 240 ms preview-entry fade; outline work stops after its 80 ms return fade. Guarded timers complete shell transitions without hidden-page frames. The halo settles idle points at y=50, owns one cancellable loop, and resets its integration timestamp on resumption. Geometry, transition origins, colours and circle bindings retain their identities; frames write numeric SVG attributes directly and update fills only when colours change. A shared mutable motion sample keeps frame updates out of Svelte's model publication path. Under reduced motion the halo reads the target tone palette directly, so a static paint does not depend on the parent effect settling that sample first.

Preview layout invalidations coalesce into one read pass before writes. Appends invalidate the last wrapped row; clip resizing and font loading invalidate all rows. Cached word geometry and a reusable caret result drive transform and opacity updates without frame-time layout reads. Advancement stops after the final caret fade. Hidden word reveals resume against their original arrival clock. Live reduced motion settles mounted word reveals and pending preview fades. Teardown disconnects observers and listeners and guards cancelled callbacks against newer transitions.

### Background mode

[background_mode.rs](../src-tauri/src/services/background_mode.rs) owns the close decision, launch visibility and the tray; [app_setup.rs](../src-tauri/src/app_setup.rs) and [lib.rs](../src-tauri/src/lib.rs) wire them. The dashboard's close handler asks `close_action`, which reads the committed `runInBackground` value from `EchoRuntime`. When it is on, the handler prevents the close and hides the dashboard. It skips owner cleanup because the dashboard holds no capture or job grant, so the overlay, hotkey and transcription continue. When it is off, or the runtime state cannot be read, the handler cleans up the dashboard's owners and exits, as in 0.3.2. Quit paths other than the dashboard close do not use this decision. Cmd+Q on macOS goes through the default app menu, which Echo does not replace, and `run` registers no exit-request handler. The tray's Quit Echo calls `app.exit(0)`. Both end in `RunEvent::Exit` and [shutdown_application](../src-tauri/src/app_setup.rs).

`apply_run_in_background` adds the tray icon (id `echo-background`) when the setting is on and removes it when off, and it is safe to repeat. It runs at startup and again from [synchronization.rs](../src-tauri/src/commands/storage/synchronization.rs) after each committed settings change, using the runtime's value so a stale revision cannot flip it. The menu is Open Echo, a separator and Quit Echo. Its event handler is registered once on the app builder in `lib.rs`, because Tauri adds a tray builder's handler to an app-wide list on every build and a per-tray handler would repeat after each toggle. On macOS the icon is a template image and a click opens the menu. On Windows the menu opens on right-click only, a left-click release shows the dashboard, and the 16 px or 32 px frame is chosen once from the dashboard's scale (32 px from 1.5). Artwork cuts are in [the brand guide](../design/brand/README.md). If the tray cannot be built, Echo logs it and leaves the setting on. A close still hides, and the macOS Dock click or a relaunch brings the dashboard back.

[tauri.conf.json](../src-tauri/tauri.conf.json) creates the dashboard hidden. At the end of setup, `show_tray_and_dashboard` looks for `--launched-at-login` in the process arguments. `dashboard_visible_at_start` returns false only when that argument is present and `runInBackground` is on, so the argument can only keep the dashboard hidden. Every other start shows it. `show_dashboard` is the single way back: Open Echo, the Windows left-click, `RunEvent::Reopen` on macOS (the overlay is always visible, so Echo does not ask whether any window is), a second launch and a normal start all show, unminimize and focus the dashboard.

[tauri-plugin-single-instance](https://crates.io/crates/tauri-plugin-single-instance) is registered first in `lib.rs`, so a second launch hands off before any other plugin starts. The second process sends its working directory and arguments to the running Echo and exits. The callback ignores both and calls `show_dashboard`. The guard keys on the app identifier on both platforms, with a Unix socket in `/tmp` on macOS and a named mutex and message window on Windows, and it applies whether or not background mode is on. It also treats a development build and a packaged build as the same app; see [development](development.md#background-mode).

[login_item.rs](../src-tauri/src/services/login_item.rs) uses the `auto-launch` 0.6.0 crate directly. On macOS it writes the LaunchAgent plist `~/Library/LaunchAgents/Echo.plist` with Echo's bundle identifier. On Windows it writes the `Echo` value under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` in current-user mode, with the path quoted. Both pass `--launched-at-login`. The name comes from `productName`, the name the NSIS uninstaller template uses to remove the Windows value; physical acceptance checks that. Each call builds the record from the running executable, so a moved Echo registers its new path. Enabling refuses a path that is not valid Unicode and, on macOS, one containing `&`, `<` or `>`, because the crate does not escape plist text. On Windows, removal and status read only HKCU through the `windows-registry` crate. Removal deletes the Run value, then Task Manager's value under `Explorer\StartupApproved\Run`. Status is true when the Run value exists and Task Manager has not disabled it, so a Task Manager disable reads as not registered, and a machine-wide HKLM entry is never read or removed. At startup `refresh_at_startup` rewrites the record only while the setting is on and the OS still lists Echo, so a removal in the OS is never undone. Its failures are logged and never block startup.

Registration runs inside the settings transaction. `update_persisted_settings` is dashboard-only and calls `update_settings_with_login_item` in [storage/settings.rs](../src-tauri/src/storage/settings.rs). That method stages the patch under the storage lock and, when `launchAtLogin` changes, registers or removes the record before COMMIT. A failure rolls the transaction back, leaves the row and revision unchanged and publishes nothing. [The command](../src-tauri/src/commands/storage/settings.rs) returns the error as `login_item_failed: <detail>`, and [background-controller.ts](../src/lib/ui/dashboard/panels/background-controller.ts) matches that prefix to show the OS detail on the Background card. If COMMIT itself fails, the OS change is made again with the previous value; a failed undo is logged, and the status check then shows the mismatch. The runtime update, tray change and settings event happen only after a successful commit, and the renderer sends no second revert write.

[get_launch_at_login_status](../src-tauri/src/commands/login_item.rs) is dashboard-only and granted in [dashboard.json](../src-tauri/capabilities/dashboard.json). [BackgroundPanel.svelte](../src/lib/ui/dashboard/panels/BackgroundPanel.svelte) reads it when the card mounts and after every `launchAtLogin` save. A difference from the saved switch shows a mismatch line that asks the user to turn the switch off and on again, and an unreadable status shows none. Known limits:

- On macOS, status only checks that the plist exists. Turning Echo off under System Settings > Allow in the Background shows no mismatch line.
- Running Echo from an App Translocation path, such as straight from Downloads or a disk image, registers a temporary path until the next normal start.
- An unsigned or ad-hoc build shows a weak name in Login Items.

Hiding the Dock icon, status rows or recording controls in the tray menu, per-machine login registration and Linux are out of scope.

## Retained native-authority decision

Decision 0004, dated 2026-09-10, chose native authority over the earlier browser-first sequencing and deferred-native plan. The retained reason is one enforceable boundary for secrets, bounded audio ownership, cancellation and revision ordering across packaged macOS and Windows flows. The renderer sends intent and opaque identities; Rust owns capture, provider work and persistence. The renderer orders delivery and invokes the native operation; it does not perform clipboard access itself.

The decision's browser preview, four-job limit and post-failure artifact reuse are superseded. The desktop runtime is the only supported runtime, current capacity is defined above, and failed dictations require new audio. The retained reversal conditions are a separately authenticated hosted service, a provider SDK requiring a reviewed native sidecar, or measured platform constraints making CPAL unsuitable. Any reversal must preserve secret isolation, bounded ownership, cancellation and revision ordering.
